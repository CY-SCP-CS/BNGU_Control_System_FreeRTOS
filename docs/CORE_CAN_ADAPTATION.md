# 新版双层总线协议适配

依据用户提供的《双层总线架构_新版.md》（2026-11-16 接口评审稿）。原文存于 CORE_CAN_PROTOCOL_SOURCE.md；原文拓扑图片仍在原始附件目录。
CAN1 承载核心应用报文，CAN2 保留各车型已有设备原生协议；DJI 电流/反馈的大端格式不因核心总线小端约定而改变。

## 已落地内容

- 公共命令类型移至 App/Modules/can/app_can_commands.h。哨兵目录只保留自身控制、机械及电机角色模型；公共协议可由其他车型复用。
- 0x111/120：8 B，平移 1 mm/s、角速度 0.001 rad/s、功率 0.01 个百分点。内部平移 m/s，允许功率使用 0～1 比率。
- 0x113：4 B，速度 int16 mm/s、转角 int16×0.0001 rad。
- 0x115：8 B，vx/vy/wz/云台角度，修正旧版的 angle/custom 布局。
- 0x121/125：4 B，yaw/pitch 目标角速度 int16×0.001 rad/s。接收时保留最新目标，控制步进按实际 tick 间隔积分；同一目标重复发送不叠加。最新姿态模式生效，切换控制源后等待新姿态命令。
- 0x123/127：4 B，绝对角度 int16×0.0001 rad；零合法，FFFF 解为 -0.0001 rad。
- 0x129：2 B，摩擦轮 00/FF，拨弹 00/AA/FF；六种合法组合均保留原始字段。00/00 不在编解码层解释为停止标志。
- 0x112：4 B，功率 int16×0.01 W 与 wz int16×0.001 rad/s；替代旧分离的 0x112/119 反馈。
- 0x122/124：4 B，角速度×1000、角度×10000；0x233：8 B，分量×30000。输出单位四元数，输入拒绝零四元数、越界分量，随后归一化。
- 移除旧版自动发送的 0x139 和 0x119，不启用未定义的 0x126、0x161 或通用 ID 转发。
- 0x031/039 原生 IMU 读请求及欧拉角区间映射，0x151/153/155/157 裁判报文均有编解码接口。
- 裁判 UART 的新鲜机器人状态/队友 HP 自动按 0x155/157 转发。热量 0x151 在选定枪口后按新鲜源字段转发。
- 辅助报文进入现有 CAN 任务发送路径，各 ID 独立最新值槽位，避免热量、场地、HP、ID 互相覆盖。
- 接收的裁判、核心四元数及可选 DM 姿态保存到 CAN 反馈快照，保留来源时间；DM 姿态不自动覆盖本地 IMU 控制输入。

## 明确的本地选择及待确认项

1. 已定义命令采用严格有效 DLC，暂不接受固定 8 B 填充的短报文。无效长度/枚举/功率范围拒收且不续期。输出采用最近整数舍入，有限数越界饱和；NaN/Inf 拒绝，角度反馈归一化到单圈。
2. 保留当前车型输入看门狗和发射/运动本地失效保护。这些超时不代表协议已经约定。CAN1 过期速度输出使用零速度/零允许功率，不再发送未定义的 -32768 停止标记。接收端也不把有效的 -32768 速度解释为专用停止指令。
3. 哨兵相对原配置标称 100 W 应用功率比例，0% 立即禁止输出；导航在 CAN 控制源下也处理 0% 禁止输出。导航缺少功率估计/测量闭环，正的功率比例目前只保留字段，不承诺精确限功率。
4. 0x120 仍使用工程既有云台/底盘安装坐标变换。零位、安装方向和对端参考系尚需共同确认；没有自动改用 DM 姿态或推定新的外参。
5. 发射优先级沿用当前本地策略：有效的显式 0x129 可覆盖发射模式，本地失效/未就绪禁止输出；摩擦轮关闭时保留禁止拨弹的本地联锁。全零载荷本身仍解为摩擦轮关、拨弹正转，不是协议急停。优先级、零角速度发射和摩擦轮关时拨弹应在联调时统一。
6. APP_CAN_DM_IMU_BUS（app_vehicle_can.h）默认 0 禁用，确认后选 1/2。RID=3、const=0 严格校验；不猜测设备物理网络，也不自动发送周期请求。调用 app_core_imu_read_request() 后由调用者填写 tick，再提交 app_rtos_core_can_submit()。不实现未定义写协议或其他寄存器响应。
7. APP_CAN_REF_HEAT_BARREL_MM（app_task_referee.h）默认 0 禁用自动 0x151，确认后选 17/42。负剩余热量按有符号数保留，越界饱和。裁判源字段按本地 1000 ms 新鲜度门控、收到有效字段更新时转发，尚无约定周期心跳。
8. 0x153 的完整字节编解码和发送入口已实现，但 2027 裁判数据中占领/RFID 等位与本文映射未确认，暂不自动拼接发送，避免用未知值假装有效状态。具备确认后的语义字段时可调用 app_core_referee_encode()，然后提交现有 CAN 任务。
9. 0x126、0x161、扩展角度与防回环转发规则未定义，继续保留。重装和导航云台自身控制仍待实现；新增公共协议不自动启用它们的电机任务。

## 验证

tests/protocol 对照原文十六进制样例检查长度、倍率、负数和各类辅助报文；tests/port 检查速度保持、变控制间隔积分、目标过期、最小速度值不触发停止哨码、0% 禁止输出以及原控制回归。
tests/host/run_tests.ps1 已包含协议测试。另编译 APP_CAN_DM_IMU_BUS=2、APP_CAN_REF_HEAT_BARREL_MM=42 的可选分支。
新旧同 ID 载荷不兼容，联调时必须同步更新 PC、云台和底盘；构建与主机测试不等于已完成实车坐标、时序和控制效果验收。
